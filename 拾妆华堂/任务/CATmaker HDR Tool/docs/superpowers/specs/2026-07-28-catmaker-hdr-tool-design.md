# CATmaker HDR Tool MVP 设计说明

## 目标

创建一个可运行的 macOS 桌面应用 `CATmaker HDR Tool`。它面向单张照片的快速视觉 HDR 增强：用户拖入 JPG、PNG 或 HEIC 图片，比较原图和处理后预览，用一个 0–2 的强度滑杆调节效果，并优先导出带 HDR Gain Map 的 HEIC；系统或编码器不支持时，明确回退为视觉增强 HEIC 或 JPEG。

这是一版便于继续迭代的 MVP，不追求完整商业修图软件的批处理、局部画笔、预设管理或照片库能力。

## 平台与交付形态

- 最低部署版本为 macOS 14 Sonoma。
- 使用 Swift 6、SwiftUI、Core Image、ImageIO、Uniform Type Identifiers 和 AppKit，不引入第三方依赖。
- 源码采用 Swift Package 组织，提供可执行产品和测试目标。
- 提供本地打包脚本，将 release 可执行文件、`Info.plist` 和资源组装为可双击运行的 `CATmaker HDR Tool.app`。
- 当前环境只有 Apple Command Line Tools，没有完整 Xcode；因此以 `swift test`、`swift build -c release`、应用包结构检查和进程启动检查作为本机验收。项目也可在安装完整 Xcode 后直接打开 `Package.swift` 继续开发。

## 用户界面

应用采用单窗口极简布局：

1. 顶部是导入区，空状态时提示“拖入 JPG、PNG 或 HEIC”，同时支持点击后通过文件选择器导入。
2. 成功导入后，中间显示等宽的“原图”和“处理后”双栏预览。图像按比例缩放，不裁切。
3. 底部提供 `HDR 强度` 滑杆，范围 `0...2`，步进 `0.01`，默认值 `1`，旁边显示当前数值。
4. 右下方提供“导出”按钮。没有有效图像或正在处理时按钮不可用。
5. 底部状态行展示最近一次导入、处理或导出的结果；失败和格式回退必须给出可理解的原因。

窗口初始尺寸约为 980 × 700 点，允许缩放，但保持预览区可用。界面只使用系统字体、颜色和控件。

## 架构与职责

### App 与界面

- `CATmakerHDRToolApp`：应用入口和窗口设置。
- `ContentView`：导入区、双栏预览、滑杆、导出按钮和状态提示，仅负责界面组合。
- `ImageDropZone`：处理文件 URL 拖放和点击导入。
- `ImagePreviewPane`：统一渲染空状态或 `NSImage` 预览。
- `EditorViewModel`：维护当前文档、强度、预览、忙碌状态和日志；协调加载、处理和导出，不包含像素算法。

### 图像与导出服务

- `ImageLoader`：用 ImageIO 验证真实文件类型、读取第一帧、应用 EXIF 方向，并保留源文件名与必要元数据。
- `HDRProcessor`：接受已定向的 `CIImage` 与强度，输出有限范围的 SDR 预览图和可用于 Gain Map 导出的扩展亮度图。
- `ImageExporter`：按“Gain Map HEIC → 视觉增强 HEIC → JPEG”的顺序尝试编码，并返回结构化的 `ExportOutcome`。
- `ExportCapability`：隔离系统版本和编码器能力判断，使回退决策可以单元测试。
- `ImageDocument`、`StatusMessage`、`ExportOutcome`：承载数据与面向界面的状态，不依赖 SwiftUI 视图。

所有 Core Image 渲染共用一个 `CIContext`，以避免频繁创建 GPU 上下文。预览渲染在后台任务中执行，结果回到主线程更新界面；滑杆变化使用短暂防抖，避免连续生成过多全尺寸图像。

## 导入流程

1. 拖放或文件选择器只接受单个本地文件 URL。
2. 文件扩展名作为选择器过滤条件，但最终由 `CGImageSourceCreateWithURL` 和源类型标识验证内容。
3. 支持 JPEG、PNG、HEIC 与 HEIF；不支持、损坏或无法读取的文件会保留现有图片并显示错误。
4. 读取第一帧，应用图像方向属性，把工作图像归一到原点，后续预览和导出使用同一方向。
5. 大图预览按窗口所需尺寸下采样；导出仍使用原始像素尺寸。

## HDR 视觉处理

处理以线性 RGB 亮度为依据，通过自定义 `CIColorKernel` 一次完成主要色调映射。强度 `s` 会被限制在 `0...2`：

- `s = 0` 时输出与输入相同。
- 暗部使用低幅度、随亮度衰减的抬升，使黑位不明显发灰。
- 中间调增益接近 1，避免画面整体变得扁平或失去自然对比。
- 高光增益从中高亮区域平滑进入，并在接近白点时逐渐压缩；最终 SDR 通道使用软拐点限制，不产生硬裁切色块。
- 根据 RGB 推导的色相、饱和度和亮度建立连续肤色权重。对于处在常见肤色范围且已较亮的像素，降低高光增益并略微抑制饱和度增长，从而降低额头、鼻梁和脸颊过曝风险。
- 肤色保护不是人脸识别，也不承诺语义级皮肤分割；它是轻量、隐私友好且适合 MVP 的颜色保护策略。

处理器同时生成：

- `displayImage`：限制在 SDR 显示范围内的视觉增强图，用于预览和回退导出。
- `extendedImage`：保留大于 1.0 的有限高光亮度，用于支持系统上的 HDR Gain Map 计算；最大内容余量由强度控制并设置安全上限。

## 导出策略

用户选择目标位置后，导出器执行以下顺序：

1. 在 macOS 15 及以上，使用 Core Image 的 HEIF 表示接口，将 SDR `displayImage` 作为基础图、`extendedImage` 作为 HDR 图交给系统计算并嵌入 Gain Map。导出后用 ImageIO 重新打开文件，并检查 HDR 或 ISO Gain Map 辅助数据是否存在；只有验证通过才报告“已导出带 HDR Gain Map 的 HEIC”。
2. 如果系统版本不足、HEIC 编码器不可用、Gain Map 写入失败或写后验证失败，尝试导出视觉增强的普通 HEIC。
3. 如果普通 HEIC 仍失败，改为 JPEG；当用户选择的目标扩展名与实际回退格式不同时，导出器使用匹配实际格式的文件名，避免内容与扩展名不一致。
4. 所有结果返回实际 URL、实际格式、是否含 Gain Map 和回退原因。界面状态必须明确显示这些信息。

PNG 仅作为输入格式，不作为导出目标；这是为了保持“优先 HEIC、最终 JPEG”的清晰 MVP 路径。

## 错误处理

- 导入错误不会清空已成功加载的照片。
- 新的处理请求会取消或淘汰旧请求，避免快速拖动滑杆后旧结果覆盖新结果。
- 导出使用临时文件完成编码与验证，成功后再原子移动到用户目标；失败时清理临时文件，不留下半成品。
- 文件选择取消不是错误，状态保持不变。
- 日志只包含格式、文件名和技术原因，不记录或复制照片内容及其他项目数据。

## 测试与验收

单元测试覆盖：

- 强度限制为 `0...2`，默认值为 `1`。
- `0` 强度保持像素不变。
- 暗部得到轻微提升，中间调变化受限，高光增强且不发生 SDR 硬裁切。
- 亮肤色样本的增益低于同亮度非肤色样本。
- 加载器接受 JPEG、PNG、HEIC/HEIF 类型并拒绝无效数据。
- 导出能力策略按 Gain Map HEIC、普通 HEIC、JPEG 的顺序回退，并保留可读原因。
- 导出后的类型与文件扩展名一致；Gain Map 成功路径必须通过 ImageIO 写后验证。

最终验收包括：

- `swift test` 全部通过。
- `swift build -c release` 成功。
- 打包脚本生成结构完整、包含正确 Bundle ID 和最低系统版本的 `.app`。
- 使用生成的样例 JPEG、PNG 和环境支持时的 HEIC 执行导入处理测试。
- 启动 `.app`，确认进程能够保持运行且无即时崩溃。
- 逐项核对拖放、双栏预览、默认强度、亮度增强、肤色保护、导出回退和状态提示均有实现证据。

## 明确不包含的范围

- 批量处理、照片库管理、预设系统、撤销历史和局部画笔。
- 机器学习人脸或语义皮肤分割。
- 完整的 XDR 显示校准、专业色彩分级或跨厂商 Gain Map 兼容保证。
- App Store 签名、公证、沙盒权限配置和自动更新。
